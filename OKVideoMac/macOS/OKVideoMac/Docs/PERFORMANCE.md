## 已设置的资源边界

- 配置 5 MiB；
- 站点响应 16 MiB；
- 海报 10 MiB，内存缓存约 128 MiB / 300 项；
- 直播列表 32 MiB；
- XMLTV 解压后 64 MiB；
- App 聚合搜索全局并发 20，Node / QuickJS / Android 分组并发均为 20；
  首批每源一页、最多 120 条，总计最多 600 条。用户向下滚动到距列表底部不足 0.75 屏时，
  自动增加一批预算并重取未完整保留的页，合并时去重。每次仅一个在途批次；静止、布局更新
  或只有替代来源增加时，不会无新的滚动需求而连续加载。正常结果无“继续”按钮。该预算同时用于 TMDB 关联搜索；
- 搜索游标最多保留 4,096 个近期 ID 与 8 个页面签名，避免被截断的大响应仍长期占用内存；
- 播放解析最多 8 次去重尝试；
- Android/Dex 远程媒体由 libmpv 直连 CDN 并直接处理 Range；Bridge 仅保留给
  Android loopback 媒体，避免模拟器二次转发造成起播、拖动和长连接回退；
- QuickJS 64 MiB / 10 秒，C smoke test 已验证无限循环中断。
- Full Guide 最多维护 48 个活跃频道行，只请求当前视口附近 1–2 个 12 小时
  时间片；Xtream demand 限制请求数与并发，并使用 5 分钟短期缓存。

## Build 171 资源调度

- EPG 在启动、导入结束（含失败与取消）、来源变更和恢复时触发后台回收。
  每次最多 4 个 512 行批次，时间预算 20 ms，尚有任务时隔 100 ms 继续；无任务便停止。
  休眠与关闭取消调度，恢复或重启续做。新导入在创建 staging generation 前分批回收废弃数据，
  沿用 Store 对 active / 有效 staging 的保护；不在前台执行 VACUUM，空闲页留给后续导入复用。
- XMLTV 每次解析最多缓存 4,096 个已解析时间戳，键长最多 128 字节；保留原有格式与时区规则。
- 播放器以 libmpv wakeup callback 通知串行队列，合并通知、每批最多处理 64 个事件。
  批次未读完时继续排队，不再每 16 ms 轮询；销毁前注销回调，直到原生销毁结束才释放上下文。
- 以上为首批实现。窗口渲染调度、Node / Android 闲置退出、内存压力策略、备份回收和真实网盘
  分阶段测速仍需独立验证；没有据此宣称 HDR、4K60、可见界面或长时间播放性能已通过。

本机 M1 / 16 GB，Release 组件使用同一套合成 XMLTV（100 个频道）复测：

| 场景 | Build 170 测试阶段耗时 | Build 171 测试阶段耗时 | Build 171 额外物理内存峰值 |
| --- | ---: | ---: | ---: |
| 5 万条 gzip，首次导入 | 9.35 s | 2.27 s | 7.6 MiB |
| 20 万条 gzip，首次导入 | 35.60 s | 6.69 s | 9.7 MiB |
| 20 万条 gzip，更新与并行查询 | 50.95 s | 8.28 s | 11.6 MiB |
| 20 万条普通 XML | 77.59 s（基线复核） | 5.57 s | 10.7 MiB |

阶段耗时包含导入、维护、查询及关闭，并非纯解析时间。各场景仅为少量独立样本，不能推断
所有来源均达到该加速比例，亦不能推断 gzip 与普通 XML 的相对速度。更新时窗口查询 P95
为 9.05 ms，100 频道 Now/Next 查询 P95 为 8.98 ms，均通过 50 ms 门槛。

实际缓存的隔离副本回收了 486,732 条废弃记录；215,766 条有效记录的数量与内容哈希保持一致，
SQLite 完整性检查通过。用户原数据库未被测试修改。清理队列与查询队列分开，避免连续清理
批次延迟节目单读取。完整证据保存在工作区本轮独立性能验收目录，不把组件测试视为可见 UI 验收。

## 0.8.0 搜索与交互变化

- CatPaw 搜索内存缓存 TTL 为 30 秒，最多 64 条/5,000 项；超过 200 项的单页和空结果
  不入缓存。配置/账号/endpoint 语义变化与手动刷新使其失效，旧代际不能回填新缓存。
- 近期 Node 响应耗时用于调整 Node 尝试次序，耗时记录最多 512 个 owner、有效 30 分钟；
  不裁掉慢站，全部已选可执行站点仍尝试第一页，非 Node Provider 次序保持。
- 首个搜索快照立即发布，后续通过 120 ms trailing timer 合并，末批结果不依赖后续响应。
  相同进行中搜索按关键词、上下文和范围复用。URLSession 单 host 连接上限同步为 20。
- Node 缓存 revision 不再当作配置语义变化；缓存通知清理可复用结果，不取消当前详情。
- 播放器视频/字幕/弹幕与控件布局分离；鼠标进度预览使用实际位置和视口坐标，工具提示
  按测量宽度限位。Seek readiness 使用当前 mpv 完成事件，不因有效关键帧偏差持续等待。
- 配置卡片准备默认 90 秒有界等待，可取消；只在真实原生交互出现后打开交互页。
  配置网页与登录等待属于已进入用户交互后的流程，不把这 90 秒当作整个登录的固定期限。
- 上述机制由回归测试覆盖；没有新增统一搜索加速百分比或 Instruments 长时测量结论。

## 播放器生命周期基线

0.3.39 的 libmpv A/B 实验已完成，详细原始数据见
[`MPV_TEARDOWN_AB_EXPERIMENT.md`](MPV_TEARDOWN_AB_EXPERIMENT.md)。

- `warmStop` 五轮关闭 60 秒的内存均值为 685.0 MB；
- `fullDestroy` 五轮关闭 60 秒的内存均值为 195.4 MB；
- 末轮稳定差值约 505 MB，主要来自 native malloc、IOSurface 和
  IOAccelerator 高水位回收；
- 完整重建 libmpv client 的可归因开销为 52–69 ms，均值约 59 ms；
- 正式五轮和 8 类极端生命周期场景未再出现销毁竞态崩溃。

该实验样本量较小，且首帧时间受网络、媒体和历史恢复影响，因此不用它
宣称 `fullDestroy` 必然提升起播速度。当前结论只是：它明显降低退出播放后的
内存高水位，未观察到可复现的二次起播退化。

## 播放期间的界面更新边界

- mpv 时间线仍以最多 10 Hz 更新播放器控件，但通过独立的
  `PlayerSnapshotState` 发布，不再触发浏览窗口的全局 `AppState` 更新；
- 首页和直播只挂载当前可见的界面树，直播会话状态由父级保留，不再使用
  `opacity(0)` 常驻不可见频道网格；
- 搜索结果聚合和直播台标解析按完整输入缓存，避免无关状态刷新时重复排序或
  执行正则归一化；
- 回归测试明确要求播放器时间线更新不会发送 `AppState.objectWillChange`。

## 弹幕与节目单渲染边界

打包前验证：Release 构建通过；25 项弹幕／真实视频全屏回归全部通过（0 失败、0 跳过）；核心弹幕测试 30 项通过，1 项既有真实服务录制样本测试因未提供专用样本跳过。本轮新增时间模型、暂停／倍速、停止帧维护后的持续运动、Retina 替换以及四次真实视频全屏循环均通过。初次发现的空屏恢复时间锚点问题已修复并完整重跑，失败证据保留。

- Build 201：滚动弹幕每条只提交一次线性 `position.x` 动画，由 Core Animation 持续呈现；`CVDisplayLink` 只调度新弹幕、回收过期对象和更新字形分辨率，不逐帧写入已有弹幕的位置。
- 动画根层时间服从播放器的平滑媒体时钟。暂停和缓冲冻结当前位置，恢复与倍速切换连续衔接；Seek、换片、来源或显式样式变化清理旧对象。普通进度纠偏最多调整播放速率的 2%，不将可见文字瞬移到新锚点。
- 保留后台 Core Text 位图、48 MiB 字形位图预算与密度上限；滑动速度仍为每媒体秒 140 逻辑点。增大窗口延长旅程，不提高速度；已经入场的弹幕保留轨迹，新弹幕使用新视口。1× / 2× backing scale 切换只替换位图。
- 全屏时弹幕位于视频缩放层之外，以相同视口顶部锚点平移，不放大字号；过渡期间保持挂载，失败或取消时清理平移。固定顶部／底部弹幕在大小变化后重新居中、贴合对应显示区域。
- 验证包括 640–3840 逻辑点宽度、24/30/60/90/120/144/165/240 Hz 虚拟时间步、0.25–2 倍速、暂停恢复、Seek、模拟 backing scale 替换与真实全屏合成。已有弹幕必须在停止主线程帧维护后仍由合成动画移动；回调测试对照屏幕刷新率，不以自身中位数掩盖半帧率。
- 本机物理屏幕为 2240×1260 逻辑点、2× backing scale、60 Hz。虚拟刷新率和模拟 Retina 切换仅验证时间／几何规则；没有声称完成 120/144 Hz、外接混合刷新率或所有 GPU 的物理显示验收。读取 presentation layer 也不等同于测量物理扫描输出。
- Full Guide 使用固定时间几何和 AppKit 按需绘制，频道行、时间轴和节目区域独立裁剪；
  刷新保留可验证的时间/频道锚点，避免重建完整节目视图树；
- 这些边界改善主线程负载与视觉连续性，不等同于所有分辨率、刷新率和弹幕密度
  组合已经完成 Instruments 长时测量。

## 播放渲染与缓存边界

- libmpv 的 VideoToolbox–OpenGL IOSurface 互操作已启用，允许支持的编码直接把
  VideoToolbox 输出交给 OpenGL，而不必固定走 `videotoolbox-copy`；
- libmpv render context 默认启用 advanced control，并在窗口遮挡、最小化或
  render surface 不可见时消费更新但跳过实际绘制；
- 远程播放默认使用 60 秒前向缓存、128 MiB demuxer 上限和 32 MiB 回看上限，
  避免长时间播放让缓存无界增长；
- 播放开始后会在 2 秒和 15 秒记录硬解模式、视频格式、估算帧率、缓存时长和
  丢帧计数，便于区分网络、解码和渲染问题；
- `OKVIDEOMAC_MPV_PERFORMANCE_PROFILE=legacy` 可恢复旧缓存行为，
  `OKVIDEOMAC_MPV_RENDER_CONTROL=legacy` 可关闭 advanced render control，
  两个回滚开关相互独立。
