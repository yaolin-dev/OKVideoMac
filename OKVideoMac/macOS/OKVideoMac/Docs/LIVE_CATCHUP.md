# 直播回放：第二阶段本地验收

状态：第二阶段实现、相关自动化回归和独立 Release 包验证完成，用户已确认播放、跳转、返回直播及顶部界面试用通过。尚未发布，不替换桌面 App。第一阶段播放信息已通过用户试用。完整 TVBox／FongMi JSON 配置、日期式节目表 API 和 Native Xtream 归档属于第三阶段。

## 操作

节目表中的历史节目按来源能力提供「播放回放」，当前节目提供「观看直播」，未来、过期、未提供回放及配置无效的节目显示对应原因。频道卡片的回放按钮打开频道节目列表；选择日期，并用前后 12 小时按钮浏览该时间段。没有历史条目时明确提示缺少节目表，不把它解释成来源不支持回放。

回放播放器顶部用两行显示节目名称，以及「回放」、频道和原播出时间，右侧保留「返回直播」。正常播放不显示等待或转圈，连接、缓冲和跳转使用中央状态提示。进度按节目起点计算。原生可跳转媒体直接跳转；按目标时间请求的来源生成剩余节目区间，保留完整节目进度。不可跳转来源禁用进度拖动。节目结束后停在结束界面，提供重新播放、已有节目表中的下一档可回放节目及返回直播。回放失败允许重试；不会自动切换为实时频道或其他频道。

## 通用 M3U 规则

支持频道及列表级 catchup、catchup-source、catchup-days、catchup-correction。频道配置覆盖列表配置；明确关闭回放的频道不会被自动开启。default 使用完整回放地址，append 将模板追加至直播地址。缺少模板、未知类型、无效时间或未知占位符不发起回放请求。

支持 UTC 秒数 utc／utcend／lutc，以及 start／end／now／timestamp 的美元符号别名；Y、m、d、H、M、S 日期字段；duration、offset 及正整数除数；如 {utc:Ymd-H-M-S} 的日期格式。catchup-correction 按小时修正请求中的节目起止时间，不改节目表时间。格式化时间默认 UTC，可用 catchup-timezone 指定 IANA 时区。catchup-startover="true" 才开启当前节目从头看；catchup-seek="native"／"request"／"unavailable" 指定跳转方式。缺少保留天数不虚构期限；明确天数用于可用性判断。

标准 IPTV 路径提供与公开上游一致的回放兼容规则：仅匹配 /PLTV/ 路径，使用 /TVOD/、playseek 起止时间及七天窗口；采用当前设备时区及重新请求方式。用户显式配置优先，不根据来源名称或频道名称推断。该兼容规则不代表所有服务端都实际保留七天内容。

## 历史节目缓存

同一来源、同一节目表修订刷新时，将过去已经观察到的、已结束的节目保留最多七天。新节目表提供的内容和时间重叠区间优先；移除的频道、其他来源或修订不会复活。缓存遵循原有条数、字节、磁盘及取消预算，不挤占新的节目表数据。没有取到过的历史节目不会被补造；视频保留期限与节目表覆盖范围分别处理。

## 验收范围

自动化使用合成节目、地址和媒体，覆盖有效期、跨日、夏令时、模板、路由身份、旧请求失效、失败、跳转、节目结束和返回直播。最后仍需对照成熟播放器及用户试用，不能仅凭地址生成或连接成功宣布来源通过验收。
