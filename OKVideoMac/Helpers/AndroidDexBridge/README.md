# OKVideoDexBridge

This optional Android helper executes FongMi Java/Dex spiders that depend on
Android `DexClassLoader` and Android-native libraries. It runs only inside the
project's headless ARM emulator and binds its RPC server to the emulator
loopback interface.

The macOS app connects through an explicit ADB loopback port forward. The
helper is not a general Java or shell execution service.

The tracked `catvod` source directory was copied from
`FongMi/TV:catvod/src/main` at commit
`5fdff00a602dc56e8ba756174daef20edab024f2` and locally modified. It is not
generated by a preparation script. Upstream copyright and `GPL-3.0-only` terms
apply. See `FONGMI_CATVOD_CHANGES.md` for the exact diff and
`THIRD_PARTY_NOTICES.md` for the complete APK runtime inventory.

## Rebuilding the bundled APK

Requirements: JDK 17, Android SDK 35/build-tools 35, and network access to the
repositories fixed in `settings.gradle`. The Gradle 8.9 wrapper distribution
hash is fixed in `gradle-wrapper.properties`; `app/gradle.lockfile` fixes the
complete Release runtime graph. Run:

```sh
./gradlew --no-daemon :app:assembleRelease
```

The Release APK is written to
`app/build/outputs/apk/release/app-release.apk`. The formal macOS package uses
the same task through `macOS/OKVideoMac/Scripts/build-android-dex-bridge.sh`.
Do not regenerate dependency locks during a release build; review and commit
lock changes separately.
