# 直播频道画面预览

0.9.0（155）包含缓存优先、有限轮次刷新、可见画面保留和最多三路受限取图；Build 145 的快速滚动退图修复继续保留。保留原生频道卡片的播放、收藏、线路、回看和节目单交互。

## 展示与缓存

- 进入直播页先读本地缓存，只自动补没有图片的频道。旧图不因时间、节目切换、刷新失败或滚动而回退到台标。图片只有成功更新后才替换。
- 图片为 640×360 JPEG。超过两分钟显示“缓存画面”，悬停查看拍摄日期和时间；缓存画面不代表当前节目内容。
- 稳定缓存键由来源、频道及 Xtream 配置身份生成，不含刷新时间、节目边界、签名 URL 或线路排序。任务有效性仍检查原目录实例／配置代次，避免旧任务跨来源写入。
- 可对应的 Build 143 缓存会按旧键读取并迁移到稳定键。
- 复用内存缓存预算 32 MiB，磁盘预算 128 MiB，按最近使用淘汰。实际可见画面另有强引用保留，数量由当前裁剪区域决定，移出可见范围即释放；不受 NSCache 随时淘汰影响。磁盘不按五分钟过期。路径为 `~/Library/Caches/com.okvideomac/live-previews-v1`，文件名只包含摘要；来源删除只清理对应图片。

## 刷新与队列

- “频道显示”菜单提供“刷新频道画面”，对当前筛选列表更新一轮，重复点击合并；频道列表／节目表刷新保持原入口。
- 默认不循环刷新。可选开启“每 10 分钟更新可见频道画面”，仅刷新过期的可见图片。
- 可见集合从布局框与实际滚动裁剪区域的交集计算，不采用 AppKit 包含预备卡片的 visibleItems。窗口缩放、列数变化、滚动均重新计算，没有固定张数。缓存读取及优先级立即跟随可见范围，节目单请求仍可延后合并。
- 可见频道优先；其中缺图优先于已有旧图。可见首轮完成后处理其慢流重试，再处理附近和其余频道。每个频道每轮最多两次尝试，失败不阻塞其余频道，也不影响源健康状态。
- 滚动只更新优先级；仍属于当前列表和来源的任务可完成并保存图片。离开直播、隐藏窗口、失活或睡眠时暂停网络取图。旧图继续保留。
- 台标请求取消及尺寸重载不会清理预览。同一来源／频道的缓存暂未入内存时继续显示已有图片；频道或来源变化、关闭预览和卡片复用会明确清除，避免串图。失焦状态可读本地缓存，但不得抓取网络或主播放器画面。
- 全局同时最多一个取帧任务。界面仅在图片更新时通知，不再每秒广播重绘。

## 主播放优先与取图

开始播放、换台或源验证前取消并回收预览任务。主播放器打开期间不新建预览连接；当前频道需要补图时，可复用同来源、频道和线路的稳定播放帧。复用截图的已取消请求同样占用 30 秒预算。

独立程序 `OKVideoLivePreview` 使用 App 自带 libmpv/bridge 离屏解码一帧后退出。地址、请求头和网络选项只经 stdin 传入，不写入进程参数、环境变量和诊断输出。

- 请求上限 64 KiB，最多 64 个请求头，拒绝换行和 NUL；只允许既有播放协议和白名单网络选项。
- 沿用播放器的默认 User-Agent、Referer 及来源请求头，Xtream 使用相同的系统代理决策。取消最低 HLS 码率强制选择，缓冲上限 16 MiB；不启用音轨、字幕、脚本。
- 初次取图预算 12 秒。失败排到当前优先级队列尾部，以 25 秒预算尝试备用线路或原慢流；包含解析的协调器硬上限为预算加 2 秒。进程自身也有截止时间，取消时终止并回收自身子进程。
- 返回 JPEG 上限 700 KiB，解码验证通过才替换旧图。失败原因区分截止时间、输入、初始化、图形、解码和导航／播放取消，不记录凭据。
- Xtream 只在账号明确报告连接额度有空余时取图；无法确认、受保护分组或需要解析的线路保留已有图片／台标。

## 验证与交付

回归覆盖 1000 频道、不同窗口尺寸、连续快速往返滚动、强制内存淘汰、保留引用释放、卡片身份与台标重载隔离、失焦时缓存与抓图隔离，以及跨重启缓存、节目边界、失败保留旧图、重复刷新合并、停止自动循环、可见优先、滚动结果保留、备用线路独立预算、LRU、旧缓存迁移和主播放抢占。真实频道验证经正式 LiveSourceParser 解析，避免测试路径改变签名转义。

只有标准 `Scripts/package-app.sh` 产出的 Release 包通过源码、签名、依赖和实际界面验证后才替换桌面 App，保留原版可回退。节目表尚无当前节目属于数据状态，不作为预览失败。


## Build 150：可见区域调度与活动详情

在已验证的 149 基础上恢复 146 的三路抓图、连接预算、快速失败与按卡片合并更新。可见区域稳定 250 ms 后按需让位，短任务保留 750 ms 完成机会；一次取消一个离屏进程，待其退出后补位，为可见任务争取最多两个优先槽位，保留一个正在完成的旧任务。正常空闲时仍只占用一条离屏预取槽位。

滚动只更新优先级；目录、路由或账户变化时重建经过完整身份验证的需求。后台活动入口使用独立状态模型，数量只驱动打开的详情；首轮包含缓存与抓图，手动刷新和自动刷新分别冻结本轮范围，滚动不重置分母。失败保留已有图片，可按源仅重试失败项。
